About

A design-thinking developer who ships

I work where design meets engineering — the place where a layout has to meet real data.

I am a web developer who enjoys the whole journey of a product: from a rough idea on a whiteboard, to a pixel-clean interface, to a deployed app that people actually use.

I care about semantic markup, layouts that behave on every screen size, accessible components, and JavaScript that stays readable six months later. On the other side of the stack I am comfortable wiring up APIs, databases and authentication so the frontend has something real to talk to.

I would rather ship something small and solid than something big and broken. And I would rather explain my choices in plain words than hide behind buzzwords.

Journey

What I am levelling up in 2026

A roadmap I actually keep to: foundations first, then depth, then shipping.

  1. Foundations

    Done

    Semantic HTML, modern CSS layouts with Flexbox and Grid, and mobile-first thinking as the default rather than an afterthought.

  2. JavaScript and the browser

    Done

    The DOM, events, fetch, async and await, ES modules — and reading DevTools properly instead of guessing at errors.

  3. Git and GitHub workflow

    Done

    Branching, meaningful commits, pull requests, and GitHub Actions doing the boring parts automatically.

  4. TypeScript in real projects

    In progress

    Generics, strict mode and typed API layers, so mistakes get caught by the compiler instead of by a user.

  5. Testing habits

    In progress

    Unit tests with Vitest and component tests with Testing Library, built into the workflow rather than bolted on at the end.

  6. Backend depth and deployment

    Next

    Authentication, database modelling, API validation, CI pipelines and monitoring — so an app stays healthy after launch day.
